## 4. Implementation Details

- `store.ts`: transaction lease obtained via exclusive file creation, fail-closed contention, full reload before request, core validation, unique temporary file and fsync-before-rename, stale source detection for direct persist, cleanup and rollback. No custom distributed lease expiry/renewal system. This small local primitive is justified as interim containment; existing PostgreSQL target remains preferred.
- `app.ts`: listens for request bodies before queueing; serializes API requests; buffers status/headers/body until transaction commit. Handler server errors discard memory, replacement failures return 503, lock contention returns 409. Security-denial audit entries may commit without business-state mutation. Existing route contract preserved where safe; unresolved closure, replay, missing rationale and stale pre-change tokens intentionally rejected.
- `auth.ts`: explicit local auth predicate and unique token nonce; API maintains session digests in optional authSessions collection, preserving compatibility with existing snapshots (old tokens intentionally invalidated). Production denies development auth; no live provider claimed.
- Worker exits 1 before reading/writing storage. API-local mock processor remains. Non-mock API mail rejected at startup until a transactional outbox supports external effects. Existing direct queue interface is still local and must not be used as an independent production writer.
- Shared ticket policy denies service interactive access, limits internal system triage, requires resolution before closure and CTO review of escalated cases. Existing documented IT/CTO organizational scope retained.
- Added read-only explicit-path migration validator (no store construction/source mutation), pinned native runtime and minimal hosted CI configuration. Hosted workflow has not run.

## 5. Security Improvements

Actor identity requires verified development token, persisted session digest and current active non-service user. Arbitrary roles/identities in request bodies do not establish privilege. Owner/SBU ticket denials and privileged route guards remain functional. Accounts disabled after login fail subsequent requests. Approval decisions serialize and cannot overwrite prior approver/rationale. CTO review cannot be bypassed by owner closure or IT state changes.

[Permission matrix](../security/ROLE_PERMISSION_MATRIX.md) distinguishes existing organization-wide IT/CTO grants from the unimplemented assigned-support-SBU/customer-organization model. Expanded SBU isolation is not accepted. Real AD/mail actions remain disabled and no LLM text executes commands. Existing tool registry keeps simulated read-only diagnostics and blocked privileged operations; approval does not turn them into real executors.

Remaining: live IdP/LDAPS, CSRF/TLS/BFF cookie design, localStorage bearer removal, OIDC revocation freshness, bound approvals, least-privilege service authentication and immutable audit. Regex secret redaction and process-local rate limits are insufficient enterprise controls.
