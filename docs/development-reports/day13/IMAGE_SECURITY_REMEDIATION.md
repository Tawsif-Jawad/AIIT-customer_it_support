## Evaluation of Three Independent Remediation Strategies

### Strategy A — Supported Patched Upstream Container Releases
- **Keycloak Investigation:** Queried official Quay.io repository (`quay.io/keycloak/keycloak`) and release channels. Tag `26.8.2` / `26.8.2-3` (`sha256:7e66a96e4739239070aeaf72e4c5decf0f7f682cfc725b9f7ea2b336eaba38b3`, published `2026-11-19`) is the latest official stable release. No newer `26.8.3` or `26.9.0` release exists upstream.
- **Samba / Debian Investigation:** Queried Debian Sources and Security Tracker APIs across `trixie`, `trixie-security`, `bookworm`, and `bookworm-security`:
  - `glibc` (`2.41-12+deb13u5`) and `zlib` (`1:1.3.dfsg+really1.3.1-1+deb13u1`) have published Debian Trixie security updates; pinning them eliminated **5 High matches** (`CVE-2026-19499`, `CVE-2026-5435`, `CVE-2026-85091`).
  - All remaining affected Trixie source packages (`python3.13=3.13.5-2+deb13u5`, `openssl=3.5.9-1~deb13u1`, `krb5=1.21.3-5+deb13u2`, `sqlite3=3.46.1-7+deb13u2`, `expat=2.9.0-1~deb13u1`, `util-linux=2.41.5-0+deb13u1`, `gcc-14=14.2.0-19`, `ncurses=6.5+20250216-2`, `cups=2.4.10-3+deb13u2`, `acl=2.3.2-2`, `cyrus-sasl2=2.1.28+dfsg1-9`, `perl=5.40.1-6+deb13u1`, `python-cryptography=43.0.0-3+deb13u1`, `dnspython=2.7.0-1+deb13u1`, `python-markdown=3.7-2+deb13u1`) are already at the latest version published in Debian Trixie.
  - Debian Bookworm LTS (`debian:bookworm-slim@sha256:734a72b3d6142a71993b4bc580ca01d8ca687f77a2c422d96a961d3376b179bc`) was built and scanned in isolation (`samba-bookworm-candidate`); it reported **3 Critical and 124 High matches** (including Critical `CVE-2025-7458` in `libsqlite3-0` and Critical `CVE-2026-5450` in `libc6`/`libc-bin`) and failed the same `--fail-on high` threshold.

### Strategy B — Supported Minimal Runtime Image Construction
- **Keycloak:** Official `quay.io/keycloak/keycloak:26.8.2` is already constructed on Red Hat `ubi9-micro` without a package manager (`dnf`/`rpm`/`microdnf` absent) and includes only the minimum glibc, OpenSSL, SQLite (`sqlite-libs`), and headless OpenJDK 21 (`java-21-openjdk-headless`) layers required by Quarkus and the JVM. Replacing `guava-33.6.0-jre.jar` inside `/opt/keycloak/lib/lib/main/` or swapping the JRE outside an official Keycloak release violates vendor support and dependency validation rules and would still leave the 1 Critical (`java-21-openjdk-headless`) and 4 High (`sqlite-libs`) UBI 9 RPM findings unresolved.
- **Samba AD DC:**
  - Evaluated dependency trees of `samba-ad-dc`, `samba-ad-provision`, `python3-samba`, `ldap-utils`, `ldb-tools`, and `ca-certificates`.
  - **Candidate B1 (Aggressive `dpkg` / `--allow-remove-essential` removal — REJECTED):** Attempted removing `gnupg` family (7 binary packages), `util-linux` family (9 binary packages), `ncurses-bin`, and `python3-markdown` in commit `ac50e59cfe6f674ffe72af19aaecbca422831e8f`. While the image built, `samba-ldaps` ([run 45121382116 / job 137516277947](https://github.com/Tawsif-Jawad/AIIT-customer_it_support/actions/runs/45121382116/job/137516277947)) failed during container startup (`Samba exited before accepting LDAPS`) because `python3-samba`'s provisioning schema modules import `markdown` (`python3-markdown`) and Debian runtime initialization relies on `Essential: yes` utilities.
  - **Candidate B2 (Validated Supported GnuPG Runtime Purge — PROMOTED):** Purged the 7 non-essential GnuPG packages (`dirmngr`, `gnupg`, `gnupg-l10n`, `gpg`, `gpg-agent`, `gpgconf`, `gpgsm`) via standard `apt-get purge -y` without `--allow-remove-essential` or `--force-depends` in commit `df217e31f1c673be5f910164dd3fa92c77a230b1`. These packages were pulled in only for archive signature tooling and are never invoked at runtime by Samba AD DC, `provision-samba.py`, or `ldapsearch`. Purging them cleanly removed **7 High matches (`CVE-2026-24882`)** while passing 100% of the `samba-ldaps` federation, scenario, and full stop/start recovery tests ([run 45121964849 / job 137518124409](https://github.com/Tawsif-Jawad/AIIT-customer_it_support/actions/runs/45121964849/job/137518124409)).
  - **Multi-stage / Distroless Feasibility:** Both `provision-samba.py` (which executes at container startup to generate ephemeral per-run passwords, certificates, and SAM database records from the mounted `/fixture` directory) and Samba's AD DC daemon (`/usr/sbin/samba`, which links directly against `libpython3.13`, `libkrb5-3`, `libssl3t64`, `libsqlite3-0`, `libexpat1`, `libcups2t64`, `libacl1`, `libsasl2-2`, `libgcc-s1`, `libstdc++6`, and `libc6`) require Python 3.13 and the C shared libraries in the final runtime container. Therefore, multi-stage separation cannot remove Python 3.13 or those shared libraries from the runtime image.
