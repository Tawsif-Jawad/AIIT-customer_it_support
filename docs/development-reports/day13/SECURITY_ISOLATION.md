# Security isolation

The SMTP adapter retains its disposable PostgreSQL configuration gate, literal loopback destination, certificate and hostname verification, and one synthetic recipient. A partial credential pair fails closed. The capture sink has no relay path. Credentials are generated per run and are excluded from output. No production credential or destination is used.

The Keycloak profile requests an internal bridge, drops capabilities, disables plain HTTP, mounts the realm and generated TLS files read-only, and publishes no ports. The authorized smoke verifies the Docker network's internal setting and absence of an IPv4 default route. This is bounded routing evidence. Container configuration must not be used as proof of OS-wide isolation.

The smoke uses a unique Compose project and removes that project's volumes and containers during cleanup. There is no Docker socket mount or privileged container. The native runner continues to use its owned disposable cluster and local services.

## Remediation implementation

The federation profile uses the existing internal Docker bridge, publishes no container ports, and forwards TLS only through a loopback fixture process for Chromium and AIIT. It executes active IPv4 (`192.0.2.1:443`), IPv6 (`[2001:db8::1]:443`), and UDP DNS (`:53`) probes from inside the Samba container to reserved TEST-NET documentation addresses and verifies that all three fail with `ENETUNREACH`, `EHOSTUNREACH`, or `EAFNOSUPPORT`. It also verifies that all Compose containers, networks, and volumes for the ephemeral project are absent after teardown.

The checksum-pinned Grype 0.122.1 job (`--fail-on high`) and Syft 1.57.2 SBOM generator scan both selected images and export machine-readable CycloneDX SBOMs, raw Grype JSON, filtered High/Critical JSON, and per-image summaries. In final remediation (`df217e31f1c673be5f910164dd3fa92c77a230b1`), purging 7 non-runtime GnuPG packages (`dirmngr`, `gnupg`, `gnupg-l10n`, `gpg`, `gpg-agent`, `gpgconf`, `gpgsm`) on top of the verified Debian Trixie `libc6`, `libc-bin`, and `zlib1g` security pins reduced Samba High findings from 151 (baseline) -> 146 (patched) -> **139 High matches** (with 5 Critical matches remaining in `python3.13`), while Keycloak `26.8.2` remains at **1 Critical and 5 High matches**. No package was ignored, no `.grype.yaml` suppression was added, no runtime isolation boundary was relaxed, and no corporate endpoint was contacted. Because upstream Red Hat UBI 9 and Debian Trixie packages do not yet provide patches for the remaining 150 High/Critical matches, the `image-scan` gate remains failed and Day 13 remains **PARTIAL**.
